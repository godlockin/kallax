# 需求分析技能

## 技能定义
将业务需求转化为技术规格的能力，确保需求的完整性和可实现性。

## 适用场景
- 新功能需求分析
- 需求文档编写
- 验收标准定义
- 范围确认

## 执行流程

### 1. 需求收集
- 利益相关者访谈
- 现有文档分析
- 用户反馈整理

### 2. 需求分析
- 功能需求识别
- 非功能需求识别
- 约束条件识别

### 3. 需求细化
- 用户故事编写
- 验收标准定义
- 优先级排序

### 4. 需求验证
- 一致性检查
- 完整性检查
- 可行性评估

## 输出格式
```markdown
## 需求分析文档

### 需求概述
- **来源**: [需求来源]
- **目标**: [业务目标]
- **范围**: [功能范围]

### 利益相关者
| 角色 | 关注点 | 影响力 |
|------|--------|--------|
| 用户 | 易用性 | 高 |
| 运营 | 效率 | 中 |
| 开发 | 可维护 | 中 |

### 功能需求

#### FR-001: [功能名称]
**描述**: [功能描述]

**用户故事**:
作为 [角色]
我想要 [功能]
以便 [价值]

**验收标准**:
- [ ] AC1: [验收标准1]
- [ ] AC2: [验收标准2]

**优先级**: P0 / P1 / P2
**复杂度**: S / M / L / XL

### 非功能需求

#### NFR-001: 性能
- 响应时间: < 200ms (P99)
- 并发支持: 1000 QPS
- 可用性: 99.9%

#### NFR-002: 安全
- 认证: OAuth 2.0
- 数据加密: AES-256
- 审计日志: 必须

### 约束条件
- 技术约束: [描述]
- 业务约束: [描述]
- 时间约束: [描述]

### 假设与依赖
**假设**:
- 用户已完成注册
- 网络环境正常

**依赖**:
- 用户服务 API
- 支付网关

### 排除范围
明确不在本期范围内:
- [功能A]
- [功能B]

### 开放问题
| 问题 | 状态 | 负责人 | 截止日期 |
|------|------|--------|----------|
| 数据迁移策略? | 待定 | DBA | 1/20 |
```

## 需求检查清单

### 完整性
- [ ] 所有功能都有明确描述
- [ ] 非功能需求已定义
- [ ] 边界条件已考虑
- [ ] 异常场景已覆盖

### 一致性
- [ ] 需求间无矛盾
- [ ] 术语使用一致
- [ ] 与现有系统兼容

### 可验证性
- [ ] 每个需求可测试
- [ ] 验收标准可量化
- [ ] 完成定义清晰

### 可行性
- [ ] 技术可实现
- [ ] 资源可支持
- [ ] 时间可满足
