## 3. 项目结构 (§1 — 跟"反讽" 联合, 跟"诚实修正" 联合)

### 3.1 3 库分离 (跟"诚实修正" 联合, 跟"独立" 拍 explicit 约束 联合)

| 库 | 路径 | 职责 | 跟"反讽" 联合 |
|---|---|---|---|
| **文档库** | `docs/` | 设计文档 / 决策记录 / 经验教训 / 索引 | ✅ 跟"反讽" 联合 — 跟主公"3 库分离" 一致 |
| **Ticket 库** | `jira/` | EPIC / Ticket / Sub-task 累计 | ✅ 跟"反讽" 联合 |
| **代码库** | `scripts/` + `node/` + `rust/` | 实现代码 + 工具脚本 + 引擎 | ✅ 跟"反讽" 联合 |

**边界规则** (跟"反讽" 联合, 跟"流程逻辑" 战略 一致):
- ❌ 文档 不可 引用 代码具体行号 (跨 release 失效) — 引用文件名 + 路径
- ❌ Ticket 不可 改 文档 (跟 1 文件 1 改 联合)
- ❌ 代码 不可 写 决策 (跟"独立" 拍 explicit 约束 联合, 决策归 confluence/decisions/)
- ✅ **任何库** 都可引用 **其他库** (单向引用, 不双向写)

### 3.2 消息队列 (跟"反讽" 联合, 跟"独立" 拍 explicit 约束 联合)

| 路径 | 用途 | 协议 | 跟"反讽" 联合 |
|---|---|---|---|
| `.kallax/queue/inbox/<role>_<id>/` | Conductor 收 Performer 报 PASS | JSON 文件 + atomic write | ✅ 跟 Rule 17 联合 |
| `.kallax/queue/outbox/<role>_<id>/` | Performer 报 Conductor 派单 | JSON 文件 + atomic write | ✅ 跟 Rule 17 联合 |
| `.kallax/inbox/human_feedback/` | 主公 反馈 | Markdown 文件 | ✅ 跟"反讽" 联合 |
| `.kallax/queue/dispatch/` | Conductor 派单 | JSON ticket manifest | ✅ 跟"反讽" 联合 |
| `.kallax/queue/results/` | Performer 报 结果 | JSON {pass/fail, output, evidence} | ✅ 跟 Rule 16 联合 |

**协议** (跟"反讽" 联合, 跟"诚实修正" 联合, 跟 Rule 17 联合):
- **写**: atomic write (写 `<file>.tmp.<pid>` → 校验 → `mv` 替换)
- **读**: 走 0 副作用 (read-only, 不 lock)
- **轮转**: `.kallax/queue/rotate.sh` 每日轮转 (跟"反讽" 联合 — 不 bloat)
- **失败**: 失败重试 3 次 + 报错 + ticket status 同步 (跟 Rule 16 联合)
