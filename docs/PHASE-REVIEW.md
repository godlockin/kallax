## 流程 (跟"反讽" 联合, 跟 Rule 6 EPIC 交付四件套 联合)

```
每 3-5 EPIC 后:
1. Master 触发 PHASE review (Rule 7)
2. Conductor 扫 本 phase 所有 EPIC 的 LESSONS-LEARNED.md
3. 5 视角 分类: 量化 / 流程 / 技术 / 治理
4. 5 扩展组 跨 EPIC 找漏洞 / 纠错 / 合并
5. Master 仲裁 + 升级:
   - 查漏补缺 (哪些 EPIC 经验教训没覆盖, 补 EPIC)
   - 纠错 (哪些经验教训跟事实不符, 改)
   - 归纳合并 (跨 EPIC 相似教训合并 → 升级 KALLAX Rule, 跟 Rule 32 联合)
   - 升级 (沉淀到 CLAUDE.md "核心原则" 或 confluence/architecture/)
6. 主公审批 (跟"独立" 拍 explicit 约束 联合) — Master 不能自己升级红线
7. 写 PHASE-XXX-REVIEW-XXX.md
8. 更新 PHASE-INDEX.md (跟 v1.3.3 模式 一致)
```
