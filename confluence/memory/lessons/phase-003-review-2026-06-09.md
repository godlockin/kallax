#### 3.4.2 升级项详细说明

**UP-1: Rule 9 增子规则 9d [P2] — Schema 完整性 = FAIL**

- **背景**: 质量 audit 维度 1 (Schema 完整性) PASS 65/65, 但 audit 工具未检测 trigger 词数量 < 20
- **建议规则**: Expert trigger 字段 < 20 词 = WARN (不 FAIL), 建议补全
- **代价**: 低, audit 工具加 1 check
- **不升级的风险**: 中, frontend/pm trigger 不足影响 M1 召回

**UP-2: Rule 9 增子规则 9e [P1] — Tier-Domain 一致性 = FAIL**

- **背景**: 质量 audit 维度 4 FAIL (10/15 generated expert 域错, 用 product/ux/finance 而非 data/legal/finance)
- **建议规则**: L3 generation 生成的 expert domain 必须在 default 7 域之外 (data/legal/finance vs product/ux/backend)
- **代价**: 中, L3 prompt 改 1 行
- **不升级的风险**: 高, 生成 10 expert 全域错, routing 到错误上下文

**UP-3: Rule 11 加 bypass 条件 [P1] — Performer 跑 design 阶段工作**

- **背景**: EPIC-028-B Performer 跑 design (无 ticket.json), scope-creep 工具误报. Design 阶段文件 scope 难以预测
- **建议规则**: `check-scope-creep.sh --bypass-design` 当 Performer 在 design 阶段 (无 ticket.json) 时 BYPASS
- **代价**: 低, 加 1 flag
- **不升级的风险**: 中, design 阶段 Performer 被误拦

**UP-4: 新 Rule 12 [P1] — 质量 ensure 强制**

- **背景**: 主公拍 "专家数量够了, 质量 ensure 一下", 质量 audit 揭露 3 真问题
- **建议规则**: Expert 数量 > 50 时必跑 `quality-audit.py`; 飞轮 "迭代" 阶段开始时必跑
- **代价**: 中, audit 工具已存在 (commit 0684f4a)
- **不升级的风险**: 高, P0-1/P0-2 问题不揭露

**UP-5: 新 Rule 13 [P1] — Worktree replica 审计**

- **背景**: 质量 audit P0-1, 32 expert 在 worktree 副本, main repo INDEX 65 vs 估算 101
- **建议规则**: 合并前必跑 worktree replica 完整性 check: `git worktree exec -- ls .kallax/experts/` vs main repo
- **代价**: 低, 1 script
- **不升级的风险**: 高, P0-1 根因 (worktree 副本被当主 repo)
