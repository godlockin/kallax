## 5 教训

### L1 — 全量 `vitest run tests/` 会挂,必须分批

**症状**: 一次跑全部 45 文件 3+ 分钟无终态,进程挂死。
**根因**: 某 hang 测试污染整批(可能 open handle / setInterval 未 unref)。
**对策**: 8 文件一批扫描,快速定位问题文件;单文件 debug 时 `--testTimeout=15000`。
**联动**: Rule §9 CLI 后台执行 + 不监控日志,分批扫是 Token Economy 实践。

### L2 — 测试期望别绑死"实现细节"

**症状 A** (expert-matcher): 测试期望 `totalScore < 1`,实际 `= 49`(baseline availability/success 非 0)。
**症状 B** (persona-schema): 测试硬编码 `security.md role=auditor` 应 fail,但 source role 已改为 `performer`。
**根因**: 测试锁死了具体数字/枚举值,source 演进后 test 未同步。
**对策**: 断言"维度性质"而非"整体总分"(如 `capabilityMatch === 0` 而非 `totalScore < 1`)。
**联动**: Immutable Eight #7 Test Isolation — 测试独立于实现细节。

### L3 — vi.mock hoisting 陷阱

**症状**: `Cannot access 'mockLogger' before initialization`(top-level var 在 `vi.mock` factory 中引用)。
**根因**: `vi.mock` 被 hoisted 到文件顶部,top-level 变量此时尚未初始化。
**对策**: 把 mock 对象**内联进** factory,或用 `vi.hoisted()` 显式声明。
```typescript
// ✅ 内联
vi.mock('../src/utils/logger.js', () => ({
  logger: { warn: vi.fn(), info: vi.fn(), debug: vi.fn(), error: vi.fn() },
}));
```
**联动**: Immutable Eight #7 DI over jest.mock,ESM 环境更甚。

### L4 — Rate limiter bucket key 必须包含 route

**症状**: 同一 IP 用两个不同 route 时,bucket size 塌陷到较小 route 的 maxTokens。
**根因**: bucket key 只用 `req.ip`,导致所有 route 共享一个 bucket(用 heartbeat 500 塞了 workflow 20)。
**对策**: `key = ${ip}::${prefix}`,`getLimitConfig` 同时返回 matched prefix。
**联动**: Immutable Eight #6 Immutability + 数据源正确性优先于 test workaround。**先修 source,不 skip 测试** — 这次没被"test skip"当做终态。

### L5 — Live tests 必须门控

**症状**: `tier-router-live` / `bridge-live` 默认跑,但需要 rust :3000 + bridge server,CI 环境必挂。
**根因**: 无环境门控,测试无条件触发。
**对策**: `describe.skipIf(!process.env.RUST_LIVE)` / `BRIDGE_LIVE`,显式 opt-in。
**联动**: Immutable Eight #4 Fail Fast — 环境不满足直接 skip,不 fail-open。
