## L2 教训

### L2-1: bash subshell + set -e 三陷阱

**现象**: `kallax-tools.sh` search 命令始终返回 0 结果，调试 2 小时找不到根因。

**根因**: 三层陷阱叠加：
1. `local cnt` 在 subshell 中声明 → 变量不传回主 shell
2. `grep -qi` 不匹配时 exit 1 → `set -e` 终止整个管道
3. `set -euo pipefail` 对 pipeline 的任意命令失败都 abort

**解法**: temp file 代替 subshell pipe 捕获变量。

**反模式**:
```bash
# ❌ 三陷阱叠加
results=$(do_scan | while ...; do
  if echo "$hay" | grep -qi "$q"; then  # 不匹配 → exit 1 → set -e 杀管道
    cnt=$((cnt + 1))  # local 在 subshell，不传回
  fi
done)
```

**正模式**:
```bash
# ✅ temp file
tmpf=$(mktemp)
do_scan > "$tmpf"
echo "0" > "$cntf"
while IFS= read -r line; do
  if echo "$hay" | grep -qi "$q" 2>/dev/null; then
    echo "MATCH:$line"
    echo $(($(cat "$cntf") + 1) > "$cntf"
  fi
  true  # guard against set -e
done < "$tmpf"
```

### L2-2: Edit replace_all 会误删函数头

**现象**: `workspace.sh` `workspace_checkpoint_save()` 函数体整个被替换，函数头丢失。

**根因**: `Edit` 工具用 `old_string` 匹配时，如果函数有多个相同开头，会全部替换。其中一个恰好是函数头的 `function_name() {`。

**解法**: 编辑函数体前先 Read 确认行号，不用 `replace_all`。

### L2-3: AWK 解析描述的边界情况

**现象**: `kallax-tools.sh` registry 描述字段出现垃圾内容（路径、逗号分隔的 tags 被解析成独立 entry）。

**根因**:
1. AWK `/^# *[A-Za-z]/` 匹配了中间注释行（如 "Layer 2: cosine"）
2. `head -2 | tr '\n' ' '` 导致多行合并后字段含 `|`，被 `IFS='|'` 误解析

**解法**: `NR > 10 { exit }` + `!/\//` 排除含斜杠的行。

---

### L2-4: `return` 不能在 script-level case 块

**现象**: `info` 命令用 `return 0` 退出 do_scan 子 shell，报错 `return: can only 'return' from a function`。

**根因**: `return` 是函数内专用，script-level case 块不是函数。

**解法**: 改 `break` 或重构为函数。

---

### L2-5: macOS `sync` 对文件无效

**现象**: `heartbeat-daemon.sh` 加了 `sync "$tmp"`，但 macOS `sync -f file` 不支持（macOS sync 只支持 `sync -f dir`）。

**解法**: `command -v sync && sync "$tmp" 2>/dev/null || true`。

### L2-6: 静态 bash registry 的维护负担

**现象**: `TOOL_REGISTRY` 静态数组每次新增 script 要改脚本本身。

**根因**: registry 和被注册对象分离。

**解法**: 动态扫描 `scripts/**/*.sh` + parse shebang/description。EPIC-122-K 实现了动态版，但花了 4 倍时间。

### L2-7: grok-build 借鉴的适用边界

**发现**: grok-build 的优势是工程实现质量（Rust/崩溃安全/MCP），KALLAX 的优势是流程治理（EPIC/PR/拍板点）。两者互补，不是竞争。

**借鉴优先级**: 工程模式（checkpoint/crash-safe）> 协议设计（ACP）> 架构重构（Workspace 抽象）>> MCP 集成。
