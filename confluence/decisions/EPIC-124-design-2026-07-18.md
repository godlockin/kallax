# EPIC-124: KALLAX MCP Bridge 原型设计

> **来源**: KALLAX 工具可被 MCP 客户端发现和调用
> **日期**: 2026-07-18
> **状态**: 设计阶段 → PENDING (2026-08-07)
> **2026-08-07 更新**: 本设计未落地 (仓库无 `node/src/mcp/` 或 Bridge server 代码)。保留供未来 backlog,详见 `confluence/research/mcp-bridge-backlog.md`。

---

## 一、背景与问题

**现状**：
- KALLAX 工具（skills）以 bash 脚本形式存在于 `scripts/` 目录
- 已有 ACP 协议（`kallax-acp.sh`）实现 JSON-RPC 2.0 over stdio
- grok-build 的 MCP 集成在 `xai-grok-mcp` crate（Rust），KALLAX 无法直接用

**需求**：
- MCP 客户端（如 Cursor、Claude Desktop）能发现 KALLAX 工具
- MCP 客户端能调用 KALLAX 工具并获取结构化结果

**约束**：
- KALLAX 是纯 bash，无法编译 Rust crate
- MCP 核心是 JSON-RPC 2.0 over stdio（与 ACP 完全一致）

---

## 二、目标

1. **MCP 兼容**：实现 MCP 协议的服务端部分，让 MCP 客户端能连接
2. **工具注册**：KALLAX skills 自动注册为 MCP tools
3. **调用转发**：MCP tool call → ACP invoke_expert
4. **最小可行**：bash 实现，只跑 stdio 模式

---

## 三、架构设计

### 3.1 两种协议的关系

```
┌─────────────┐     MCP JSON-RPC 2.0      ┌──────────────────┐
│ MCP Client  │ ←────────────────────────→ │  kallax-mcp.sh   │
│ (Cursor/    │       over stdio           │  (MCP Gateway)   │
│  Claude     │                            │                  │
│  Desktop)   │                            │  - protocol      │
└─────────────┘                            │    translation   │
                                           │  - tool registry │
                                           └────────┬─────────┘
                                                    │ ACP JSON-RPC 2.0
                                                    ↓
                                           ┌──────────────────┐
                                           │  kallax-acp.sh   │
                                           │  (已有)           │
                                           └──────────────────┘
```

**结论**：kallax-mcp.sh 是 MCP-to-ACP 网关，不是替代关系。

### 3.2 实现路径选择

| 路径 | 优点 | 缺点 |
|------|------|------|
| A. bash stdio | 零依赖，与 ACP 共用 | 并发弱，无 HTTP+SSE |
| B. HTTP+SSE | 支持更多客户端 | bash 无法稳定实现 |

**选择**：路径 A（bash stdio）

理由：
- KALLAX 纯 bash，stdio 最稳定
- MCP 客户端（Cursor/Claude Desktop）都支持 stdio 模式
- ACP 已验证 bash stdio 可用

### 3.3 MCP 协议映射

MCP 协议核心方法：

| MCP 方法 | 用途 | KALLAX 对应 |
|----------|------|-------------|
| `initialize` | 握手+协议版本协商 | ACP session_open |
| `tools/list` | 列出所有工具 | 扫描 scripts/ skill 注册 |
| `tools/call` | 调用单个工具 | ACP invoke_expert |
| `ping` | 保活 | ACP query_invocations（简化） |

## 四、API Schema

### 4.1 MCP Initialize

**Request**：
```json
{
  "jsonrpc": "2.0",
  "method": "initialize",
  "params": {
    "protocolVersion": "2024-11-05",
    "capabilities": {},
    "clientInfo": {"name": "cursor", "version": "0.1.0"}
  },
  "id": 1
}
```

**Response**：
```json
{
  "jsonrpc": "2.0",
  "result": {
    "protocolVersion": "2024-11-05",
    "capabilities": {"tools": {}},
    "serverInfo": {"name": "kallax-mcp", "version": "1.0.0"}
  },
  "id": 1
}
```

### 4.2 tools/list

**Request**：
```json
{
  "jsonrpc": "2.0",
  "method": "tools/list",
  "params": {},
  "id": 2
}
```

**Response**：
```json
{
  "jsonrpc": "2.0",
  "result": {
    "tools": [
      {
        "name": "kallax-init",
        "description": "Initialize KALLAX workspace",
        "inputSchema": {
          "type": "object",

        }
      },
      {
        "name": "kallax-status",
        "description": "Show KALLAX status",

  "id": 2

```

**Request**：

## 五、Tool Registry 设计

### 5.1 注册来源

KALLAX skills 自动注册，来源：
1. `scripts/kallax-*.sh` — 主 skill 脚本
2. `scripts/verify/check-*.sh` — 验证脚本（作为工具暴露）
3. `scripts/permission/*.sh` — 权限脚本（按需暴露）

### 5.2 注册格式

每个 skill 对应一个 `.kallax/tools/<name>.json`：

```json
{
  "name": "kallax-status",
  "description": "Show KALLAX status dashboard",
  "script": "scripts/kallax-status.sh",
  "inputSchema": {
    "type": "object",
    "properties": {
      "verbose": {"type": "boolean", "default": false}
    }
  }
}
```

### 5.3 扫描与缓存

```bash
# 启动时扫描，生成 tool registry
scan_tools() {
  local registry_dir=".kallax/tools"
  mkdir -p "$registry_dir"

  for script in scripts/kallax-*.sh scripts/verify/check-*.sh; do
    local name
    name=$(basename "$script" .sh)
    # 从脚本头部提取 description（约定格式）
    local desc
    desc=$(grep -m1 "^# Description:" "$script" | cut -d: -f2- | xargs)
    # 生成 JSON schema（简化：空对象或从注释推断）
    jq -n \
      --arg name "$name" \
      --arg desc "$desc" \
      --arg script "$script" \
      '{name: $name, description: $desc, script: $script, inputSchema: {type: "object", properties: {}}}'
  done > "$registry_dir/registry.jsonl"
}
```

## 六、调用链路

### 6.1 完整调用时序

```
MCP Client                    kallax-mcp.sh                 kallax-acp.sh
   |                                |                            |
   |--- initialize ----------------→|                            |
   |←-- initialize result -----------|                            |
   |                                |                            |
   |--- tools/list ----------------→|                            |
   |←-- tools/list result ----------|                            |
   |                                |                            |
   |--- tools/call ----------------→|                            |
   |                                |--- session_open ----------→|
   |                                |←-- session_id --------------|
   |                                |                            |
   |                                |--- invoke_expert --------→|
   |                                |←-- invocation_id ----------|
   |                                |                            |
   |                                |--- query_invocations ----→|
   |                                |←-- result -----------------|
   |                                |                            |
   |←-- tools/call result ----------|                            |
   |                                |                            |
```

### 6.2 错误处理

| 错误类型 | MCP 错误码 | 处理 |
|----------|------------|------|
| Invalid method | -32601 | 返回 method not found |
| Invalid params | -32602 | 返回 invalid params |
| Tool not found | -32602 | 返回 tool not found |
| Script error | -32603 | 返回 script output as error |
| Timeout | -32603 | 返回 timeout after 300s |

## 七、与 ACP 协议的关系

### 7.1 统一 vs 分离

**结论**：统一，不是分离。

理由：
1. ACP 已实现 JSON-RPC 2.0 over stdio，MCP 也是
2. 两者协议格式高度相似（initialize/tools/call 语义相同）
3. MCP 是 ACP 的超集（多了 tool schema）

### 7.2 融合路径

```
Phase 1: MCP Gateway（独立进程）
    kallax-mcp.sh → kallax-acp.sh

Phase 2: 协议统一
    合并到 kallax-acp.sh，加 --mode mcp|acp 参数

Phase 3: 渐进替换
    删掉 gateway，直接在 acp.sh 处理 MCP 方法
```

**Phase 1 MVP**：独立 gateway，不动已有 ACP 代码。
