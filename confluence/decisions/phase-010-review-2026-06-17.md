## 5. 经验教训 (跟"反哺框架" 战略 一致)

### 5.1 主题 1: 串行派单 vs 并行派单

**教训 1**: 4 subagent 并行 → silent output 复发 BE-9 反讽. 1 ticket 1 subagent 串行 → 100% PASS deliver.

**教训 2**: Subagent 上下文预算上限存在. 4 subagent × 详细 prompt (含 4 工具 CLI 实测 + 8 AC + 8 anti-patterns + raw test output) → silent output. 串行 1 subagent × 1 ticket = 完整 deliver.

**教训 3**: 跨 ticket 依赖 (057-B 用 057-A paths, 057-C 用 057-A+B paths, 057-D 用全部) 不能并行. 串行是 hard requirement, 跟"独立" 拍 explicit 约束 联合.

### 5.2 主题 2: "跨平台 fix release" 反讽治根

**教训 4**: Release naming 跟实现状态必须一致. v2.0.2 自称"跨平台" 但 install.sh 仅 Claude Code → 反讽. v2.0.6 install.sh `--target=auto` 检测 4 工具 → naming = reality.

**教训 5**: "v2.0.2 release 命名是跨平台, 实际只 Claude Code (历史 gap), v2.0.6 治根" 必须明确标注 (跟"诚实修正" 联合, 不模糊处理).

### 5.3 主题 3: hybrid flag-controlled install

**教训 6**: `--target=auto` 默认 = 全支持 (跟"翻篇&精进" 一致, 用户**不需要选**, 但**可以选**).
`--target=a,b` 多工具逗号 = 灵活 (跟 EPIC-054-A worktree 统一 联动, RootBucket invariant).

**教训 7**: opencode singular `/command/` vs plural 是历史 trap. 4 工具 paths 必须实测, 跟 EPIC-053-A l3-l4-consistency 联动.

### 5.4 主题 4: ticket design gap (跟"诚实修正" 联合)

**教训 8**: ticket 假设 vs 实测. 057-B ticket 假设 `opencode --non-interactive` flag, 实测不存在 → fallback to `opencode run` subcommand. Performer 修 design gap + 标 honest mark.

**教训 9**: 057-F ticket 假设 `jira/tickets/**/pass-report*.json` gitignore pattern 够, 实测 subagent runtime 还有 `test-output*.txt` 跟 `test_result*.json`. Master amend ticket.json file_scope (跟之前 13a06efa cleanup 模式 一致).
