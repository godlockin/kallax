## 2. Dockerfile 设计 (多阶段 builder → runtime, 跟 root Dockerfile 模式 一致)

### 2.1 架构

```
Stage 1 (builder):  node:20-alpine
                     └─ COPY package.json
                     └─ npm install --omit=dev (http-server only)

Stage 2 (runtime):  node:20-alpine
                     └─ COPY --from=builder node_modules + package.json
                     └─ COPY src/dashboard + index.html + styles.css + app.js
                     └─ USER kallax (non-root, uid 1001)
                     └─ EXPOSE 8080
                     └─ HEALTHCHECK wget http://localhost:8080/
                     └─ CMD npx http-server src/dashboard -p 8080 -c-1 --silent
```

### 2.2 关键 设计决策

- **多阶段 builder → runtime**: 避免 devDeps 泄到 runtime image (跟 v2.7.4 root Dockerfile 模式 一致)
- **non-root user**: uid 1001 (跟 root Dockerfile `kallax` user 模式 一致)
- **HEALTHCHECK**: wget spider (避免 curl, 减少 image size)
- **cache-control `c-1`**: 部署环境 0 缓存 (deployment-ready, 0 stale)
- **DEFAULT_PORT=8080**: 跟 API server 9877 端口隔离 (env var `DASHBOARD_PORT` 可 override)

### 2.3 跟 root Dockerfile 互为 互补

| 维度 | root `Dockerfile` | `web/Dockerfile` |
|------|-------------------|-------------------|
| Base | node:20-alpine + rust:1.75-alpine | node:20-alpine only |
| 用途 | API server (port 9877) | 静态 dashboard (port 8080) |
| 运行时 | node + rust binary | http-server (Node.js zero-dep) |
| 镜像大小 | 较大 (含 Rust 工具链) | 较小 (only http-server + web/*) |
| 多阶段 | 4-stage (rust-builder, node-builder, production, development) | 2-stage (builder, runtime) |

**0 端口冲突** (8080 vs 9877, 跟"硬性脚本" 5 原则 联合).
