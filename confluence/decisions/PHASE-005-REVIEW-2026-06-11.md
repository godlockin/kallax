#### 3.4.2 升级项详细说明

**UP-1: 新规则 Rule 9d [Commit Amend 验证]**

- **背景**: EPIC-031 3 Performer amend 连续失败 KPI falsification, 缺工具防御
- **建议规则**: 所有 commit --amend 前必跑 check-commit-amend-verify.sh (4 维度: amend 标识 / SHA 变化 / reflog 痕迹 / working tree 一致)
- **代价**: pre-commit hook 多 1 工具, ~1s overhead
- **不升级的风险**: 3 amend 失败反复, Conductor 验证成本高

**UP-2: 新规则 Rule 11 v2 [Master 写代码禁令硬红线]**

- **背景**: 主公 2026-06-09 原话"除了极端情况, master 不许写代码", EPIC-031 Pe1 验证
- **建议规则**: Master 默认禁止写代码, 唯一例外是极端情况 #4 (主公明示"你来干")
- **代价**: Master 需更强自律, Performer 失败时走重试而非接管
- **不升级的风险**: Master 接管常态化, 角色边界模糊

**UP-3: 新架构文档 [dispatch-audit.md派发审计 7 字段]**

- **背景**: EPIC-031 T3 派发决策审计 7 字段 (timestamp/ticket_id/algo_suggest/final_slaver/decision/actor/type)
- **建议规则**: 所有派发决策必写 .kallax/audit/dispatch-YYYY-MM-DD.jsonl, 7 字段完整
- **代价**: audit-db.sh 新 SQLite, schema 设计
- **不升级的风险**: 派发权让渡后无审计, 责任不清

**UP-4: 新架构文档 [trustscore-fail-closed.md TrustScore fail-closed]**

- **背景**: EPIC-031 T2 TrustScore fixture fallback 静默接受 state/instances.json 导致 dispatch 跑错 fixture
- **建议规则**: fixture fallback 必须 env var 强制 + 优先级最高, 缺 fail-closed
- **代价**: trust-score.sh 改优先级逻辑
- **不升级的风险**: dispatch 跑错 fixture, E2E FAIL

**UP-5: 新规则 Rule 9e [Tier-Domain 一致性]**

- **背景**: EPIC-024 quality audit 揭露 10/15 generated expert 用 product/ux/finance (跟 default 7 域冲突)
- **建议规则**: default tier 必用 {architect, backend, frontend, ux, product, security, pm}, generated tier 不在 default 7 域
- **代价**: expert-quality-audit.py增强检查
- **不升级的风险**: Tier-Domain 混乱, E2E 匹配失效

**UP-6: 修订 Rule 13 [3 模式决策权]**

- **背景**: EPIC-029 3 模式 (ai-auto/ai-copilot/manual) + EPIC-031 派发权让渡, 需统一表述
- **建议规则**: Rule 13 补充派发权让渡模式 (算法骨架 + 人工拍板, 60% AI + 40% 人工)
- **代价**: CLAUDE.md Rule 13 修订
- **不升级的风险**: 3 模式和派发权让渡表述不一致

## 10. Phase 2 (5 专家 Master 合并担任)

按主公 2026-06-11 拍"Phase 2+3 Master 合并" (1 conductor 容量限制), Master 担任 5 专家视角, 输出每专家 1-2 漏洞 + 升级建议.

### 10.1 Backend 视角
- **漏洞 1**: EPIC-031 TrustScore 4 因子算法用 `bc` 计算, 不支持任意精度 (浮点误差 ≤ 0.01)
  - 升级建议: 改 Python `decimal` 或 Rust `f64::EPSILON`, 保持精度
  - 优先级: P2 (技术债, 不影响功能)
- **漏洞 2**: EPIC-030-B scoring-trace.sh + EPIC-031-C dispatch-audit.sh 都写 `.kallax/audit/scoring-*.jsonl`, 但路径冲突 (B 是算法 trace, C 是决策 audit), 共享 file → 数据混淆
  - 升级建议: 拆 `scoring-algorithm-*.jsonl` (B) + `dispatch-decision-*.jsonl` (C) 或加 `type:` 字段分流 (C 已加 type:dispatch)
  - 优先级: P1 (审计可追溯, 跟 Rule 3 产出验证机制)
  - **状态**: ✅ EPIC-031-C 已加 `type:dispatch` 字段分流, 跟 B 兼容 (B 写 algo, C 写 dispatch)

### 10.2 Frontend 视角
- **漏洞 1**: 3 模式 session_start.sh 菜单 ASCII 渲染跟现有 ASCII card 风格不一致 (用 "MODE* ▸ $MODE" 但其他字段用 "ROLE ▸ ..."), 用户认知负担
  - 升级建议: 统一 "ROLE ▸ conductor" + "MODE ▸ ai-copilot" 风格 (无 * 后缀)
  - 优先级: P2 (UX 微调)
- **漏洞 2**: 13 套 E2E 测试脚本命名规范不统一 (e.g. `state-schema-test.sh` 跟 `permission-v1-e2e.sh` 后缀不一致)
  - 升级建议: 统一 `-test.sh` 后缀, 跟 EPIC-031 衍生脚本一致
  - 优先级: P3 (低, 跟 Phase 5 升级无强关联)

### 10.3 UX 视角
- **漏洞 1**: 3 模式选错后, 提示不明确 ("Select mode [1/2/3]" 但模式名跟编号映射没显式说明)
  - 升级建议: 加一行 "1=ai-auto (AI 自主, 仅 block/danger 停下问) / 2=ai-copilot (默认) / 3=manual (每阶段主公确认)"
  - 优先级: P1 (主公友好, 跟 3 模式借鉴 A1)
- **漏洞 2**: `whoami.sh` 输出 mode 字段没标 "(当前模式)" 后缀, 用户看不明白
  - 升级建议: 改成 `mode: ai-copilot (当前)` 显式
  - 优先级: P2

### 10.4 Product 视角
- **漏洞 1**: EKET 借鉴清单 (10 P0 + 8 P1 + 8 P2) 已落地 9 P0 (EPIC-030), 但 8 P1 + 8 P2 16 项**没明确落地时间表**
  - 升级建议: 写 EKET 借鉴总进度表, 含 P0/P1/P2 完成度 + 预计落地时间
  - 优先级: P1 (飞轮"迭代"前置)
  - **建议 Master 产出**: `confluence/decisions/EKET-BORROW-PROGRESS-2026-06-11.md`
- **漏洞 2**: M1 co-evolution 50 test case 一直推迟, 4 个 generated expert 闲置 (finance×4 + product×3 + ux×3), 浪费 L3 generation 投入
  - 升级建议: M1 50 test case 拆 EPIC-032, 1d 落地
  - 优先级: P0 (跟 10.1 漏洞 1 同)

### 10.5 Security 视角
- **漏洞 1**: 3 轮安全审查落地 13 issue, 但**没加持续 audit 机制** (半年 review redaction 新 token prefix)
  - 升级建议: 加 `scripts/verify/check-redaction-audit.sh` 季度跑, 比对 redaction pass 数 + 新增 secret prefix 库
  - 优先级: P1 (跟 DEBT-D 衔接)
