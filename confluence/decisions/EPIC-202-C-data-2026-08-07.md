## 4 Lessons

### 1. 文档跟实际不一致就是 CRITICAL
**教训**: doc-audit-flow.md 写 3 阶段, 实际跑 5 EPIC, future performer 跟文档会迷.
**应用**: future 流程固化文档必 grep git log 验证历史 EPIC, 跟实际一致才定稿.

### 2. L1-L5 raw evidence 是 docs-only EPIC 5-Level Verify 必需
**教训**: docs-only EPIC 无 cargo test / vitest run, 但 L2 (raw stdout) 仍可填 test script output + grep raw data.
**应用**: future docs-only EPIC 拍板记录必含 L1-L5 evidence 段, 不只贴 "0 stale" 摘要.

### 3. DRY Rule 是 business logic 不是文字字串
**教训**: "archive-not-delete" 重复 22 处每文件1行 — 这不是 DRY 违规 (Rule 5 治代码逻辑, 不治注释字串).
**应用**: future code review 不要把注释字串重复当 DRY 违规. 重点是 extract 函数 / 类型 / 配置.

### 4. 工具 bootstrap paradox 文档化接受
**教训**: doc-audit-flow.md 说 Phase 1 用 check-internal-refs.cjs, 实际工具在 EPIC-199 才建 — paradox. 但工具随 EPIC 增量开发是正常节奏, 文档应 forward reference "工具待 Phase 3 落地", 不假装存在.
