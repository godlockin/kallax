# EPIC-122-E: events.jsonl per EPIC 设计方案

> **来源**: grok-build workspace session `events.jsonl` per session 模式
> **日期**: 2026-07-18
> **状态**: 设计阶段

---

## 一、现状问题

**当前问题**：
- `~/.kallax/state/state.json` 的 `expert_invocations[]` 是全局数组
- 所有 EPIC/Ticket 的调用混在一起，查询要全量扫描
- 无法按 EPIC 独立追溯调用历史
- `expert_invocations` 在 state.json 里，跟 queue 持久化是分离的

**grok-build 模式**：
```rust
// workspace/session/session.rs
session_event_writers: DashMap<String, EventWriter>  // per-session events.jsonl
```

每个 session 一个 `events.jsonl`，append-only，并发安全。

---

## 二、目标

1. 每 EPIC 一个 `expert_invocations.jsonl`（追加写入）
2. 每 Ticket 一个 `invocation_records.jsonl`（EPIC 子集）
3. 全局 state.json 保留，但不存完整调用历史（只存 counts）
4. 向后兼容：现有 queue 文件不变

---

## 三、Schema 设计

### 3.1 EPIC 级别 jsonl（每 EPIC 一个）

路径：`~/.kallax/queue/EPIC-XXX/invocations.jsonl`

```jsonl
{"expert_id":"backend-architect","ticket_id":"EPIC-104-TASK-002","ts":1752850000,"backend":"sqlite","output_length":1423,"output_truncated":false,"role_id":"architect"}
{"expert_id":"sre-engineer","ticket_id":"EPIC-104-TASK-003","ts":1752850060,"backend":"file","output_length":897,"output_truncated":true,"role_id":"sre"}
```

每行一个 invocation record，append-only。

### 3.2 Ticket 级别（可选，用于细粒度追溯）

路径：`~/.kallax/queue/EPIC-XXX/tickets/TICKET-XXX/invocations.jsonl`

只是 EPIC jsonl 的子集，用于快速查某 Ticket 的历史。

### 3.3 state.json 简化

```json
{
  "expert_invocations_count": 142,  // 全局计数
  "expert_invocations_last_epic": "EPIC-104",  // 最后活跃 EPIC
  "expert_invocations_last_ts": 1752850060
}
```

不再存完整数组，避免 state.json 膨胀。

## 四、队列降级链扩展

```
EPIC jsonl (append)  ← 主要路径
    ↓ (降级)
file jsonl (append)  ← 已有
    ↓ (降级)
SQLite (已有)
    ↓ (降级)
Redis Stream (已有)
```

**EPIC jsonl** 是新加的最优先层。

## 五、目录结构

```
~/.kallax/queue/
├── EPIC-104/
│   ├── invocations.jsonl      # EPIC 级别，所有 invocation
│   └── tickets/
│       └── TICKET-002/
│           └── invocations.jsonl  # 可选：Ticket 级别
├── EPIC-105/
│   └── invocations.jsonl
└── ... (每个 EPIC 一个目录)
```

## 六、迁移方案

**Phase 1（向后兼容）**：
- 写：同时写 state.json expert_invocations[] + EPIC jsonl
- 读：优先读 state.json expert_invocations[]（兼容旧逻辑）
- EPIC jsonl 是新字段，旧代码忽略

**Phase 2（清理）**：
- 迁移脚本：`scripts/migrate-invocations.sh`
- 把 state.json expert_invocations[] 导出到对应 EPIC jsonl
- 清空 state.json expert_invocations[]，换成 count 字段

**Phase 3（仅 EPIC jsonl）**：
- state.json 不再写 expert_invocations 数组
- 读取全走 EPIC jsonl

---

## 七、并发安全

- 用 `with_lock "epic_invocation"` 做写锁
- append 用 `>>`，不需要读全部再写
- LRU archive 在 append 后触发（行数超 10000 触发 archive）

---

## 八、Backward Compatibility

| 组件 | 旧版本 | 新版本 |
|------|--------|--------|
| state.json | expert_invocations[] | expert_invocations_count (Phase 3) |
| queue file | expert_invocations.jsonl | 同路径不变 |
| emit() | 写 state + queue | 写 EPIC jsonl + state |

Phase 1 完全向后兼容。
